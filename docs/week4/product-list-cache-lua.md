# 목록 캐시 Lua 읽기 측정

상세 캐시를 Lua 읽기(왕복 1회)로 바꾼 뒤(`detail-cache-design.md` 3.1), 목록 첫 페이지 캐시도 같은 방식으로 바꿀지 판단하려고 쟀다. 목록은 값이 상세보다 커서, **데이터까지 master 가 보내는 부담**이 상세와 다르다는 점이 판단의 쟁점이다.

- 실험 코드: `ProductListCacheLuaExperiment` (`RUN_EXPERIMENT=true`), 목록용 Lua 변형: `LuaProductListCache` (테스트 소스에만 있음, 상세와 같은 `VersionedCacheScript` 사용)
- 실행일: 2026-10-18, MySQL 8.0 · Redis 7.0 단일 노드 Testcontainers, **두 번 실행**
- 데이터: `seed/week4-product-seed.sql` (상품 1만 개, 목록 측정과 같음)

## 1. 측정 방법

- 포트(`ProductListCache`)를 바꿔 끼우는 구현을 `@Primary` 로 두고, 같은 컨텍스트에서 방식만 바꿔 같은 요청을 보낸다.
  - **C:** 제품 코드(`RedisProductListCache`). 버전은 master, 데이터는 replica 우선 연결로 읽는다. 왕복 2회
  - **Lua:** 실험 변형. 버전과 데이터를 스크립트 한 번으로 master 에서 읽는다. 왕복 1회. 키 · 저장 형식 · 무효화는 C 와 같다
- 측정 전에 두 방식의 응답 본문이 같고 hit 의 SQL 이 0개인지 확인했다.
- 장면마다 회차별로 두 방식을 번갈아(순서를 돌려) 잰다. 준비 500회차 뒤 3,000회차.

## 3. 관찰

1. **Lua 는 C 보다 p50 이 약 0.25~0.33ms, 비율로 약 33~35% 짧다.** 두 장면 · 두 실행 모두 같은 방향이다. 상세(약 0.35~0.42ms, 35~40%)와 비슷한 비율이다.
2. **값이 약 3KB 여도 Lua 의 이득은 줄지 않았다.** 이 환경에서는 Redis 가 3KB 를 보내는 시간보다 왕복 하나를 없애는 효과가 컸다.
3. **브랜드 7 장면이 전체 장면보다 느린 것은 측정 순서 때문으로 보고 해석하지 않는다.** 브랜드 7 을 먼저 쟀고, 값 크기는 거의 같다(나눠 재지 않음).
4. **master 송출 부담은 이 환경에서 재지 못했다.** master 와 replica 가 같은 노드라, C 에서 replica 가 맡던 데이터 송출이 Lua 에서 master 로 옮겨 가는 효과가 지연에 나타나지 않는다.

## 4. 판단 자료: master 송출량 어림

hit 1건당 master 가 보내는 양(응답 데이터 기준, 프로토콜 오버헤드 제외)으로 어림한다.

| 방식 | master | replica |
|---|---|---|
| C | 버전 약 13 bytes | 데이터 약 3KB |
| Lua | 버전 + 데이터 약 3KB | 없음 |

초당 hit 수를 곱하면 Lua 로 바꿀 때 master 가 더 보내는 양이 나온다.

| 초당 목록 hit | Lua 의 master 추가 송출 |
|---|---|
| 1,000 | 약 3MB/s (약 24Mbps) |
| 10,000 | 약 30MB/s (약 240Mbps) |
| 50,000 | 약 150MB/s (약 1.2Gbps) |

- 트래픽 규모는 가정이 없다. 실서비스라면 목록 초당 hit 수와 Redis 서버의 네트워크 한도를 놓고 판단한다.
- 키 하나에 몰리면(`all` 범위) 이 송출은 모두 master 한 대가 맡는다. 단일 스레드인 Redis 에서 큰 값을 보내는 일이 몰리면 다른 명령의 대기도 늘 수 있다(재지 않음).

## 5. 한계

- 같은 PC 의 컨테이너라 왕복이 짧고, master · replica 가 같은 노드다. 운영에서는 C 의 추가 왕복이 더 길고(Lua 이득 증가), 동시에 master 송출 부담도 실제로 생긴다(Lua 대가 증가).
- 한 스레드의 순차 요청이다. 동시 요청에서 master 가 큰 값을 보내는 부담은 재지 않았다.
- 장면 두 개(브랜드 7 · 전체), 상품 1만 개 상태에서 두 번 실행했다.
